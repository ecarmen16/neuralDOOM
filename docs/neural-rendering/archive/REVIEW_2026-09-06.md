## Remaining limits

RTX is a hybrid static-BSP renderer with one diffuse bounce, not full path tracing. Moving characters, doors and props do not cast ray-traced occlusion. Bounce uses simplified material stages, geometric normals, up to 16 visible light stages and a view-dependent raster radiance cache. Animated emissives, camera turns and occlusion changes need visual assessment. There is no new ray-traced reflection pass. Native HDR retains the documented gamma-space HUD composition prototype.

The local source installer is ready for playtesting on this configured machine; fresh-machine installation is still unverified. An NR DLL path/URL does not assemble the entire legacy bridge. Native RTX/HDR needs no NR runtime. Retail data and third-party binaries remain outside Git.

## Three checks for playtesters

1. Launch `Launch-NeuralDoom-RTX.cmd`, choose DLAA, and use 5120x1440 borderless with Windows HDR. Try FOV 70 and HUD Auto (16:9); confirm the HUD and settings survive a relaunch.
2. Run `exec neural_rtx_keys.cfg`. Near a colored light/corner, compare F6 (bounce), F7 (AO), F8 (contacts) and F11 (all). F10 provides isolated views; mode 4 shows ray-material albedo. The earlier elevator view had subtle bounce, so also compare a lit room.
3. Walk, turn, fire, watch an animated character/door, then reload a save. Check for trails, flashes or lighting pops. Optional logs: `neuralBackendStatus`, `rayTracingGIStatus`, `hdrStatus`.

Next work should respond to this playtest. Reflections or dynamic ray geometry should follow a stable lighting/motion baseline.
